# План реализации

1. Тесты и реализация `AppStorage`: атомарный кэш справочника (24 часа),
   выбор области по ISO, срок следующего запроса отдельно для двух API.
2. Подключить хранение к старту, смене области и обработке ответа; добавить
   файлы в обе системы сборки и проверить C++-тесты.
3. Тесты и запись истории подтверждённых и недоступных наблюдений. Реализовать
   Python CLI с HTML/CSV/JSON-отчётами и честным учётом пробелов наблюдения.
4. Добавить локальную SVG-карту HTML/CSS/JS и окно WebView2. Связать выбор
   и статусы с VCL; добавить открытие Python-отчёта из приложения.
5. Проверить полную сборку, IDE, Python, поведение веб-карты и реальный
   повторный запуск. Обновить краткую пользовательскую документацию.

Не изменять способ хранения API-ключа; не передавать его в Python или JS.
Сохранять существующие исходники и не включать личную историю в Git.

## Результаты проверки

- Выполнены все пять этапов; сборка `build.ps1` и Win32 Base из `.cbproj` успешны.
- 220 проверок C++/ASM (включая 26 проверок хранения), 11 Python-тестов,
  4 JavaScript-теста и интеграционная проверка запуска отчётов пройдены.
- Проверено восстановление выбранной области после перезапуска; с кэшированным
  справочником первое подтверждение API пришло в ту же секунду, что и старт.
- Встроенная веб-карта получила реальные статусы C++; в браузере проверены
  выбор области, масштаб, выключение подписей и переход в неизвестное состояние
  при устаревших данных. Двойной клик после исправления приближает область.
- Из приложения созданы HTML/CSV/JSON-отчёты по локальной истории.
- Независимый обзор выявил передачу переменных ключей через окружение и
  неявный поиск Python в рабочей папке. Обе проблемы исправлены; синтетические
  проверки подтверждают отсутствие ключей в дочернем процессе и поиск только
  по явным абсолютным путям. Python запускается в изолированном режиме `-I`.
- Дополнительно проверена граница потери связи и восстановления в одну секунду:
  она не создаёт ложное новое начало тревоги в статистике.
